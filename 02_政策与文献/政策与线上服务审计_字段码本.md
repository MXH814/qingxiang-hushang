# 政策与线上服务信息字段审计码本

## 目的

以公开官方页面为观察单位，记录一个首次办事青年能否在页面中直接找到关键行动信息。审计只判断“页面是否明确呈现”，不评价部门绩效，不把研究者的常识补入页面。

## 编码口径

- `1`：页面正文或明确可见组件中直接出现该字段；
- `0`：页面未出现、仅笼统提及、需要跳转后才能获得，或无法在公开状态核验；
- `NA`：该字段对该类页面不适用。当前数据尽量不用NA，便于比较不同信息载体的覆盖差异。

## 字段

| 字段 | 判定标准 |
|---|---|
| issuer_visible | 发布/实施主体明确 |
| publish_date_visible | 发布或更新日期明确 |
| effective_period_visible | 生效、失效或活动期限明确 |
| audience_visible | 服务对象/适用人群明确 |
| eligibility_visible | 受理或申请条件明确 |
| identity_branches_visible | 按租住、就业、学籍、交易方式等情形分支 |
| materials_visible | 材料名称或材料目录明确 |
| steps_visible | 办理顺序或步骤明确 |
| channels_visible | 办理渠道明确 |
| offline_fallback_visible | 线下窗口或人工替代渠道明确 |
| time_limit_visible | 办结、申请、入住或活动时限明确 |
| result_visible | 办理结果或可取得凭证明确 |
| cost_visible | 是否收费或价格信息明确 |
| consultation_visible | 咨询电话、在线帮办或窗口咨询明确 |
| faq_or_example_visible | FAQ、常见错误或情形示例明确 |
| direct_online_entry_visible | 页面提供可直接进入办理/申请的官方入口 |
| update_or_expiry_visible | 页面明确提示版本、有效期或动态核验需求 |
| cross_service_relation_visible | 明确说明与前后事项或其他服务关系 |
| mobile_channel_visible | 明确说明APP/微信/支付宝等移动渠道 |
| risk_or_ineligible_visible | 不予办理、异常情形、风险或边界明确 |
| plain_language_summary_visible | 存在面向普通用户的摘要、问答或简明说明 |

## 质量控制

1. 每行保存URL、页面标题、发布主体、访问日期和截图路径。
2. 编码依据写入`evidence_note`，优先使用页面原词，不复制大段原文。
3. 规范性文件和服务指南不是同一功能载体；分析重点是字段分布与跨页跳转，不以总分评优。
4. 页面动态更新后，新建版本记录，不覆盖旧行。
5. 第二名团队成员应复核全部0/1编码；分歧保留记录后协商，不按预期结论修改。
